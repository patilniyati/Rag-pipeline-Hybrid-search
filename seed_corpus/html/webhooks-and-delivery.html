Webhook Signing and Delivery

Lifecycle events are delivered through the notify queue to the workspace endpoint. Delivery is at-least-once: consumers must tolerate the same event arriving more than once.

Signature validation

Each delivery includes X-Northstar-Signature. The signature uses HMAC-SHA256 over the timestamp and raw request body. Verify the signature against the exact raw bytes before parsing JSON, and reject timestamps more than five minutes away from the local clock. Keep the webhook signing secret separate from the API key.

Retries

A non-2xx response or connection timeout is retried up to six delivery attempts across a 24-hour window. The endpoint should return a 2xx response quickly and move expensive work to an internal queue. A successful response acknowledges receipt; it does not guarantee that the consumer's business workflow has completed.

Deduplication

Use the event ID as the consumer-side deduplication key. Record the event ID before performing a non-idempotent side effect, or use a transaction that atomically records the ID and result. Do not use delivery attempt number as a unique event identifier.

Diagnostics

When investigating missed events, capture the event ID, endpoint identifier, delivery attempt, response status, and UTC timestamp. Never include the signing secret or the full payload if it contains customer data.
