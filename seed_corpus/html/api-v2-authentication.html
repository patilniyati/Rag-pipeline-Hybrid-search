API v2 Authentication

Northstar Relay authenticates each API request with a workspace key. This page covers credential transport, error interpretation, and key rollover.

Send the key

Send the credential in the X-Northstar-Key HTTP header over TLS. Production keys begin with ns_live_; sandbox keys begin with ns_test_. Do not include a key in a URL, query parameter, browser-visible script, or log line.

Rotation cadence

Rotate production keys every 90 days or immediately after suspected exposure. The previous key has a 24-hour overlap window after rotation. Deploy the replacement to every dependent service, verify successful authentication, and revoke the old key before the overlap ends. Keep sandbox and production credentials separate.

Authentication failures

401 means a key is absent, malformed, expired, or revoked. 403 means the key was recognized but its identity lacks permission for the requested operation. Repeated 401s after a rotation usually mean one or more workloads still hold the old credential.

Audit and response

Key creation and revocation are written to the administrative audit log. If a key leaks, revoke it first, identify the earliest plausible exposure time, inspect its audit activity, and rotate dependent secrets. Never paste a secret into a ticket.
