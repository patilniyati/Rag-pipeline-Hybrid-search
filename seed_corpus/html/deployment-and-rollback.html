Deployment and Rollback Procedure

Northstar Relay deployments use a canary followed by a gradual traffic shift. The release owner records the baseline and monitors the service before advancing.

Canary sequence

  1. Capture the stable pre-deployment p95 latency and 5-minute error rate.
  2. Send 10% of production traffic to the candidate version.
  3. Observe for at least 15 minutes, including one normal job-submission cycle.
  4. Advance traffic only if error rate, latency, queue age, and worker saturation remain healthy.

Rollback triggers

Roll back if the 5-minute API error rate rises more than 1.0 percentage point over baseline, or if p95 latency exceeds 2 times the pre-deployment baseline. The reliability policy also pages the API on-call when p95 exceeds 500 ms for five consecutive minutes above the traffic floor.

Rollback steps

  1. Stop the traffic shift and keep the last stable version available.
  2. Return traffic to the stable version.
  3. Verify 5xx rate, p95 latency, dispatch queue age, and DLQ-17 counts.
  4. Post a release-channel update with the change, impact, rollback time, and owner.
  5. Preserve logs and the deployment identifier for the incident review.

Do not suppress an alert simply because the deployment has been rolled back; confirm that the underlying metric returned to its healthy range.
